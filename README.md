# ReviewRadar

AI-powered repo auditing and code review reporting.

ReviewRadar is a lightweight script that inspects a repository, runs multiple security and quality checks, merges the results, ranks the issues by severity, and produces a clean PDF report for review.

This project is designed for fast repository triage, code review support, security audits, and developer-friendly reporting.

## Why this project exists

When reviewing a project, engineers often need a quick but structured answer to questions like:

- Does this repo have vulnerable dependencies?
- Are there hardcoded secrets or API keys?
- Are there risky code patterns or unsafe security assumptions?
- Can I generate a shareable report for stakeholders or team review?

ReviewRadar answers that by combining several scanners and consolidating the output into one easy-to-read report.

## What it checks

The script can look at:

- Git repositories
- local project folders
- single files

It uses tools for:

- dependency vulnerability scanning
- secret detection
- static analysis
- misconfiguration checks
- report generation

## Quick start

```bash
chmod +x ./audit_repo.sh
./audit_repo.sh <target> [output-dir]
```

Examples:

```bash
./audit_repo.sh https://github.com/juice-shop/juice-shop
./audit_repo.sh ./my-project
./audit_repo.sh ./snippet.py
```

## Optional modes

### Build and test mode

```bash
RUN_BUILD=1 ./audit_repo.sh ./my-project ./audit-report
```

This runs build and test steps in the target repo. Use this with caution and ideally inside a safe environment like Docker or a VM.

### Report-only mode

```bash
REPORT_ONLY=1 ./audit_repo.sh ./my-project ./audit-report
```

This skips new scanning and rebuilds the report from existing output data.

### No-PDF mode

```bash
NO_PDF=1 ./audit_repo.sh ./my-project ./audit-report
```

This generates the Markdown report and findings JSON without creating the PDF.

## Requirements

### Required

- `git`
- `python3`

### Optional tools for richer results

The script automatically checks for and uses these if available:

- `osv-scanner`
- `npm`
- `trivy`
- `gitleaks`
- `semgrep`
- `reportlab`

If a tool is missing, the script records that fact in the report instead of simply failing.

## Output

Running the script creates a report folder such as `./audit-report` containing:

- `Security_Audit_Report.pdf`
- `REPORT.md`
- `findings.json`
- scanner logs and raw outputs
- `overview.txt`
- `tool_status.tsv`
- `meta.env`

## Severity ranking

Findings are grouped as:

- Critical
- High
- Medium
- Low

This helps prioritize the most dangerous issues first.

## Important note

The output is generated by automated tools and may include false positives. The script itself advises manual verification before acting on a finding.

This is best used as a first-pass audit tool, not as a final judgment.
